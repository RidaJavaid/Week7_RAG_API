Retrieval-Augmented Generation, or RAG, combines information retrieval with language-model generation. A typical RAG pipeline loads source documents, splits them into chunks, indexes those chunks, retrieves evidence for a user question, and then asks a language model to answer using the retrieved context. Retrieval should be evaluated before generation because a generator cannot reliably use evidence that was never retrieved. Source citations improve traceability by showing which document or chunk supported an answer. A grounded system should avoid inventing facts that are not present in its evidence. A useful fallback is I don't know when retrieval confidence is too low or the retrieved context does not support an answer. Sparse retrieval such as BM25 focuses on lexical term evidence. Dense retrieval uses semantic embeddings. Hybrid retrieval combines sparse and dense signals to improve candidate coverage. Reranking applies a stronger but slower relevance model to a small candidate set. A CrossEncoder jointly reads the query and candidate passage and outputs a relevance score. Evaluation should compare retrieval before and after each component, and a component that does not improve measured quality should be removed or revised.
